# P0.1 — Project Foundation

**Status:** Completed  
**Phase:** Phase 0 — Architecture and Security Specification

## Objective

Establish a durable repository baseline that makes the Master Architecture, project governance, security expectations, contribution workflow, and development continuity available from Git rather than chat history.

## Scope

P0.1 is repository and documentation work only. It does not introduce a Rust workspace, production dependencies, platform integrations, transport implementations, UI code, or third-party research source code.

## Deliverables

- `docs/architecture/MASTER-ARCHITECTURE.md`
- `README.md`
- `.gitignore`
- `SECURITY.md`
- `CONTRIBUTING.md`
- `docs/adr/README.md`
- `docs/development/WORKFLOW.md`
- `docs/development/ROADMAP.md`
- `docs/development/CURRENT.md`

## Dependencies and Governing References

- Cross-Lab Master Architecture & Development Plan
- ADR governance and change-control requirements in the Master Architecture

## Decisions and Constraints

- Git history, repository contents, and verification results are the factual implementation record.
- `docs/development/CURRENT.md` is the resume guide, not a replacement for Git or accepted architecture.
- Material architecture changes require an ADR and explicit approval.
- Important work must be committed and pushed before interruption or context handoff.
- Research repositories remain reference material until license, security, maintenance, platform, and architectural fit are reviewed.
- Secrets, credentials, private keys, tokens, and recovery material must never be committed.

## Acceptance Criteria

P0.1 is complete when a fresh developer can determine the project purpose, architecture source of truth, contribution/security rules, current milestone, branch/workflow expectations, ADR process, and exact next task from the repository alone.

## Verification

The repository entry documents and continuity workflow were reviewed for internal consistency, unsupported implementation claims, accidental secret material, and alignment with the Master Architecture. No Rust build checks were applicable because no Rust workspace existed in this milestone.

P0.1 was integrated into `main` through Pull Request #1.

## Handoff

P0.1 hands the repository to P0.2 for the foundational threat model and trust-boundary specification.
