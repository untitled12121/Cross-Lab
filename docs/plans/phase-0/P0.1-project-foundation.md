# P0.1 Project Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish the first durable Cross-Lab repository baseline with the authoritative architecture document, project entry documents, ADR structure, and Git-first continuity/resume workflow before production Rust implementation begins.

**Architecture:** This milestone is documentation and repository-governance only. It creates the files future sessions use to reconstruct project state, while preserving the approved Cross-Lab Architecture Baseline v2.0 unchanged as the primary source of truth. No production feature code, Rust workspace, transport dependency, UI dependency, or third-party research code is introduced here.

**Tech Stack:** Git, GitHub, Markdown.

**Spec:** `docs/architecture/MASTER-ARCHITECTURE.md`

## Global Constraints

- The Cross-Lab Master Architecture & Development Plan Revision 2.0 is the primary architectural source of truth.
- Do not silently change approved architecture; material architecture changes require an ADR and approval.
- Chat history is working context only; Git/code/tests and repository documentation are the durable project record.
- No production feature implementation belongs in P0.1.
- No Rust dependencies, GPUI, Quinn, Iroh, libp2p, UniFFI, database, plugin runtime, or platform integration are introduced in this milestone.
- The repository license remains an explicit open architecture decision; do not select or imply a license without approval.
- Do not adapt source code from uploaded research repositories until licensing/reuse requirements are satisfied.
- Never commit credentials, API keys, private keys, tokens, recovery material, or other secrets.
