# P0.7 Session and Transport Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Freeze secure logical-session authentication, channel binding, reconnect/revocation semantics, and the Cross-Lab-neutral transport contract required by the simulator and first Quinn milestone.

**Architecture:** Logical sessions own Cross-Lab identity/protocol/capability/authorization state. Transports provide protected byte/stream channels plus opaque cryptographic channel binding; transport identities never replace Cross-Lab credentials. Reconnect creates a new session and fresh authentication in Phase 1.

**Tech Stack:** Markdown specification. No transport implementation is introduced during P0.7.

**Spec:** Master Architecture Sections 11, 12, 15, 16, 37, 38, 42, 44-47 plus P0.3-P0.6 specifications.

## Global Constraints

- Cross-Lab authentication remains independent from transport identity.
- Untrusted real links require confidentiality/integrity before ordinary protected session traffic.
- Session authentication signs a fresh transcript bound to an opaque transport channel-binding value.
- Phase 1 has no 0-RTT authorization, session resumption, or cross-transport authority migration.
- Reconnect requires a fresh session/authentication and does not inherit operation IDs.
- Concrete Quinn/Iroh/libp2p types stay outside domain/core contracts.
