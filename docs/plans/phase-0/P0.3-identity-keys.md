# P0.3 Identity and Key Hierarchy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Freeze the owner/device identity hierarchy, credential roles, stable identifiers, epochs, rotation semantics, and private-key handling constraints required by Phase 1.

**Architecture:** Cross-Lab identity remains independent from transport and platform accounts. Owner authority is separated into root, device-signing, administrative, and recovery roles; each device owns separate device key material. Stable domain identifiers are distinct from rotatable key identifiers.

**Tech Stack:** Markdown specifications and ADRs. No implementation dependencies are added in P0.3.

**Spec:** `docs/architecture/MASTER-ARCHITECTURE.md` Sections 4, 6, 7, 37, 42, 44.

## Global Constraints

- Preserve transport-independent identity.
- Do not reuse one private key for owner root, device signing, administration, recovery, and device authentication.
- Keep recovery authority separate from ordinary trust.
- Private keys remain local and are hardware-backed where practical.
- Stable `OwnerId`/`DeviceId` semantics must survive ordinary key rotation.
- Do not include mutable capability/platform metadata in identity credentials unless it is security-critical and intentionally versioned.
- Any selected cryptographic profile is recorded in an ADR and remains subject to Phase 0 architecture review.
